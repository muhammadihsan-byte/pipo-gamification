## First implementation batch (this PR)

1. **Reuse a single component system.** `TicketCard` gains an optional `approvedCompact` style while retaining its unchanged default 24pt surface. No parallel card container is introduced.
2. **Figma Budget B:** 18pt corner radius, 16pt horizontal inset, 15pt top and 13pt bottom inset, white surface and Figma `#E2E8F0` outline. Figma accent source is `#E54569`; because its small text contrast is only approximately **3.90:1 on white**, headings, total, and Edit labels use accessible `#D4315B` (approximately **4.78:1**) instead. Body follows `#0F172A`; secondary text `#475569`. This intentional accessibility deviation is not an unapproved card style.
3. **Truthful data:** row percentages = `row / actual target`, rounded. Data comes from persisted SwiftData or the existing plan draft, never hardcoded Figma Rp samples. A mismatched breakdown remains visibly mismatched, and invalid amounts get a review message. No updates to goal amounts, XP, achievements, billing, group membership, Supabase or the saving engine.
4. **Interaction:** the **existing Edit target** action in plan review remains available and at least 44pt; Goal Detail presents read-only itemization until #42 plan editing exists. Cards expand with Dynamic Type and longer texts; no clipping to the 230pt sample canvas.
5. **Brand:** existing `PersonalPlanStyle.pink` is already exact approved **#FF6584**. `PipoTheme.pink` currently differs and must be reconciled in **#20** before globally restyling all controls; this batch does not change unrelated primary buttons.

## Focused QA and blockers

- [ ] One controlled iOS build and targeted XCTest for percentages (68/23/9 sample ratios), mismatched totals, zero target, invalid amount and preservation of row identity.
- [ ] Native screenshot/MP4 review against [Budget B selected example](https://www.figma.com/design/tce3nRBcRwyObJMwQzA2rK/Gamification-Saving-SaaS?node-id=1223-6775), using actual logged values (not sample Bali data), small and large text, VoiceOver semantics, goal/account switching.
- [ ] Real-device signed QA for saved items, long names, error and offline states remains a release gate separate from simulator success.
- [ ] Review remaining families in small PRs: Goal Focus/Progress (coordinate #41/#43) → Milestones/Empty (#40/#19) → overview and input/impact/history (#42/#16). Do not mix unimplemented money-out or real group sync into visual parity work.
